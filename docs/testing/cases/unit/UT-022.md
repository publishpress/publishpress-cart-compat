# Legacy compatibility is enabled by default

## Scenario

The plugin ships a `ncs_cart_legacy_compat_enabled()` toggle that gates whether legacy class aliases are registered. With no `NCS_CART_LEGACY_COMPAT` constant defined and no filter overriding the value, the toggle must report that legacy compatibility is switched on. This guarantees existing integrations relying on old class names keep working out of the box.

## Steps

1. Run the unit suite with no WordPress bootstrap; the stubbed `apply_filters` returns the unmodified value because no `ncs_cart_legacy_compat_enabled` filter is registered.
2. Do not define the `NCS_CART_LEGACY_COMPAT` constant.
3. Call `ncs_cart_legacy_compat_enabled()`.

## Expected result

`ncs_cart_legacy_compat_enabled()` returns `true` (default-on), since neither the constant nor the filter forces it off.

## Edge cases

- The default must stay `true` even when the surrounding environment has no WordPress functions beyond the stubbed `apply_filters`.
