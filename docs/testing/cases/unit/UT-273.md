# First-party webhook and invoice use canonical query vars

## Scenario

Prefix slice 43 switches public webhook and invoice routes to
`ppcart-webhook` / `ppcart-api` / `ppcart-invoice`. First-party emits and
reads the canonical names. Leftover `sc-*` inbound URLs live in
publishpress-cart-compat.

## Steps

1. Read `public/class-ppcart-public.php` rewrite, query vars, and webhook handler.
2. Read `ppcart_get_webhook_url()`, Stripe/PayPal emitters, and invoice emit/read.
3. Scan first-party PHP under `admin/`, `includes/`, `public/`, and `models/`.
4. Assert canonical names are present and leftover `sc-webhook` / `sc-api` /
   `sc-invoice` are absent.

## Expected result

- Rewrite and query vars register `ppcart-webhook` / `ppcart-api` /
  `ppcart-invoice`.
- Webhook URLs emit `/ppcart-webhook/{gateway}` or `/?ppcart-api=`.
- Invoice links emit and handlers read `ppcart-invoice`.
- First-party PHP has no leftover slice-43 names.

## Edge cases

- Leftover `sc-*` 302/rewrite/POST copy is Compatibility Mode only (UT-274 /
  IT-344).
- `admin_post_sc_stripe_webhook_manual_setup` is slice 47.

Implemented in publishpress-cart.
