# Pro custom tables use live helpers and Compatibility Mode leftover SQL rewrite

## Scenario

Pro first-party SQL uses canonical `{prefix}ppcart_*` table names (via
`ppcart_pro_live_table()`). Compat `ppcart_live_table()` must follow leftover
`ncs_affiliates*` / `ncs_tax_rate` names when those tables still exist.
Compatibility Mode must rewrite leftover table names in SQL onto the live name
so leftover SQL still works after Data migration. There is no silent
`RENAME TABLE`.

## Steps

1. Stub leftover-only Pro tables; call `ppcart_live_table()` for each Pro family.
2. Stub canonical Pro tables; call the helpers again.
3. Stub empty `SHOW TABLES`; call the helpers.
4. Load `ncs_cart_get_legacy_custom_table_map()`.
5. Call `ppcart_rewrite_legacy_custom_table_sql()` with Compatibility Mode off, then on.

## Expected result

Leftover-only installs return leftover Pro table names and leftover affiliate
metadata type/column. Canonical or empty installs return `{prefix}ppcart_*`.
The Compatibility Mode map lists leftover suffixes. Query rewrite is off when
the mode is off and leftover → live when the mode is on. `SHOW` / `ALTER` /
`RENAME` / `CREATE` schema probes are not rewritten. After migration, leftover
`$wpdb->ncs_affiliatemeta` is re-pointed at the live table while Compatibility
Mode is on.

## Edge cases

- Canonical wins when both leftover and canonical tables exist.
- Merchant `RENAME TABLE` is IT-366.
- Free tax/order-item families stay on UT-220 / IT-300–305.
