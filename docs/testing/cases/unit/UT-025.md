# Class alias is skipped when compatibility is disabled

## Scenario

`ncs_cart_register_class_alias()` must respect the compatibility toggle. When the `ncs_cart_legacy_compat_enabled` filter forces compatibility off, calling the registrar must not create the legacy alias, even though the canonical class exists.

## Steps

1. Register a stub `ncs_cart_legacy_compat_enabled` filter whose callback returns `false`.
2. Declare a global canonical stub class `NCS_Cart_CompatAliasDisabled`.
3. Call `ncs_cart_register_class_alias('NCS_Cart_CompatAliasDisabled', 'CompatAliasLegacyDisabled')`.

## Expected result

`class_exists('CompatAliasLegacyDisabled', false)` returns `false` — no alias is created while compatibility is disabled.

## Edge cases

- Skipping must occur even though the canonical class `NCS_Cart_CompatAliasDisabled` is fully available.
