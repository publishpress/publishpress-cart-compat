# Post-meta helpers map leftover keys and query leftovers only in Compatibility Mode

## Scenario

First-party post/user-meta writes use `_ppcart_*`. Helpers accept a suffix, leftover `_sc_*` name, or canonical name. WP_Query / SQL leftover keys are included only while StudioCart Compatibility Mode is on and the merchant-run migration is not complete. Leftover product-duplicate rewrite lives in cart-compat (UT-247).

## Steps

1. Call `ppcart_meta_key()` / `ppcart_legacy_meta_key()` with `pay_options`, `_sc_pay_options`, and `_ppcart_pay_options`.
2. Call `ppcart_query_meta_keys('amount')` with Compatibility Mode off.
3. Enable Compatibility Mode and call the query helper again.
4. Mark meta-key migration complete and call the query helper with Compatibility Mode still on.
5. Expand a `meta_query` that mixes `_thumbnail_id` and leftover `_sc_amount`.

## Expected result

All three inputs map to `_ppcart_pay_options` / `_sc_pay_options`. Queries return only `_ppcart_amount` unless Compatibility Mode is on and migration is incomplete, in which case they return both keys. Unrelated `meta_query` keys such as `_thumbnail_id` stay unchanged.

## Edge cases

- Dual-read get helpers are not this query gate.
- `get_prefix()` is `ppcart_` (IT-281).
- The Compatibility Mode-off query case skips in the full unit suite when UT-184 has already defined `PPCART_STUDIOCART_COMPATIBILITY_MODE`; run `Prefix/MetaKeyMigrationTest` in isolation to cover it.
- The `pre_get_posts` expander only rewrites leftover `_sc_*` and canonical `_ppcart_*` keys.
