# Settings page slug is canonical ppcart without a legacy bridge

## Scenario

The Compatibility Mode Settings API page identifier must be unique (`ppcart`). Plugin identity now uses `ppcart`, so the temporary `ncs-cart` page bridge must be removed.

## Steps

1. Read `PPCart_Studiocart_Compatibility_Mode::SETTINGS_PAGE`.
2. Check that `SETTINGS_PAGE_LEGACY` is not defined.

## Expected result

Canonical page is `ppcart`, and no legacy Settings API page constant remains.

## Edge cases

- The Settings API page identifier is separate from the canonical wp-admin
  settings slug `ppcart-settings`.
