# Gateway helpers read leftover processor metadata only when a lookup is registered

## Scenario

Pro writes canonical Mollie/Razorpay/Square/Stripe-tax processor keys.
`ppcart_pro_mollie_metadata()`, `ppcart_pro_razorpay_notes()`, Square catalog
candidates, and `ppcart_stripe_metadata()` read leftover `sc_*` keys only when
a Compatibility Mode lookup is registered. Canonical wins when both keys are
set. There is no silent migrate.

## Steps

1. Load Mollie, Razorpay, Square, and Stripe metadata maps.
2. Call each helper with leftover-only bags, with and without a registered lookup.
3. Call with both canonical and leftover keys present.
4. Enable Compatibility Mode and register the real Compat lookups.
   Leftover Mollie `sc_order_id` must resolve onto `ppcart_order_id`.

## Expected result

Leftover-only values are empty until the lookup is registered. Canonical wins
when both are set. Empty canonical (`0`) falls through to leftover while the
lookup is registered. Square leftover `#sc_plan_` is a candidate only after
the lookup is registered.

## Edge cases

- Stripe `sc_subscription_id` leftover remains UT-235.
- Processor objects live at the gateway; there is no WordPress row rewrite.
