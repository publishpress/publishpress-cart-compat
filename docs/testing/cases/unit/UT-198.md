# Compatibility query mapping is gated and safe

## Scenario

StudioCart Compatibility Mode owns the complete legacy-to-canonical public
query map and applies it only to safe public requests while the feature is on.

## Steps

1. Verify the six legacy and canonical query-var pairs.
2. Register query vars with Compatibility Mode off and on.
3. Map multiple scalar values, including `0`, plus a resolved download key.
4. Pass an array-shaped value and a canonicalized stale download result.
5. Map a request containing both canonical and legacy forms of one key.
6. Check GET/HEAD, POST, admin, AJAX, and REST redirect policy contexts.

## Expected result

Legacy query vars register only while Compatibility Mode is enabled. Scalar
values map deterministically, canonical values take precedence, arrays are
ignored, canonical requests do not loop, and only public GET/HEAD requests are
eligible for redirect.

## Edge cases

- String zero remains a valid value.
- A canonical download query suppresses remapping of a stale resolved legacy
  query var.
