# Product duplicate leftover meta rewrite lives in cart-compat

## Scenario

PublishPress Cart Free is canonical-only: it never rewrites leftover `_sc_*`
product meta on duplicate, and product/order setup only reads `_ppcart_*`
from `get_post_custom()`. publishpress-cart-compat owns leftover → canonical
rewrite on duplicate, leftover Stripe product-id exclusion, and leftover
setup hydration via `ppcart_setup_*_from_meta`.

## Steps

1. Call `ppcartcomp_product_duplicate_meta_key('_sc_pay_options', …)` with
   leftover-only source meta.
2. Call again when both leftover and canonical twins exist.
3. Call `ppcartcomp_product_duplicate_excluded_meta_keys()` with the canonical
   Stripe product id already excluded.

## Expected result

Leftover-only keys rewrite to `_ppcart_*`. Leftover twins are skipped when a
canonical row already exists. Canonical keys pass through. Leftover
`_sc_stripe_prod_id` is added to the exclude list.

## Edge cases

- Free without cart-compat skips writing any `_sc_*` key on duplicate.
- Accepting leftover `default_fields` POST ids remains Compatibility Mode gated.
- Merchant Data migration (`PPCartComp_Meta_Key_Migrator`) renames all leftover
  `_sc_%` postmeta/usermeta rows (including product/profile keys Free no longer
  rewrites). Covered by IT-281.
