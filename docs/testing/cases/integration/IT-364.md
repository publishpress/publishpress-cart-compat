# Canonical Pro meta reads leftover rows without copying

## Scenario

Stored leftover `sc_sq_cc_id` and `sc_custom_meta` rows must satisfy first-party
`get_post_meta( ..., 'ppcart_sq_cc_id' )` / `ppcart_custom_meta` without copying
or deleting leftover rows. Storage read-through is always-on so Pro works with
Compatibility Mode off. Canonical wins when both rows exist.

## Steps

1. Insert leftover `sc_sq_cc_id` and `sc_custom_meta` on an order.
2. Read canonical keys with Compatibility Mode off.
3. Confirm leftover keys still return the leftover values.
4. Confirm an unmapped canonical key stays empty.

## Expected result

Canonical reads return leftover values. Leftover rows stay in place. No silent
migrate.

## Edge cases

- Nested `get_post_metadata` must not recurse (depth guard before exists checks).
- Leftover `get_post_meta( ..., 'sc_sq_cc_id' )` after Data migration is Compat-on leftover API.
