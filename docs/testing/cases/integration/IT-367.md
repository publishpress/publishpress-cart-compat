# Data migration rewrites leftover MemberPress trans_num and affiliate submission meta

## Scenario

Merchant-started `ppcart_migrate_third_party_stored_keys()` rewrites leftover
MemberPress `sc-txn-` trans_num values to `ppcart-txn-` and leftover affiliate
meta `sc_submission_id` to `ppcart_submission_id`. Plugin upgrade does not do
this. Canonical wins when both names already exist. There is no silent migrate.

## Steps

1. Create a MemberPress transactions table with leftover `sc-txn-41` and a
   conflicting `ppcart-txn-42` pair.
2. Insert leftover `sc_submission_id` into affiliatemeta, plus a conflict row.
3. Run `ppcart_migrate_third_party_stored_keys()`.
4. Confirm leftover-only rows moved and conflict leftover rows stayed.

## Expected result

Leftover-only MemberPress trans_num and affiliate meta keys become canonical.
Conflict rows keep leftover. Migration is opt-in.

## Edge cases

- Compatibility Mode leftover trans_num lookup is UT-315.
- Affiliate leftover API is Compat-on; storage read-through is always-on.
