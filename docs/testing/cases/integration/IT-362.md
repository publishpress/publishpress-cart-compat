# Leftover sc/v1 Pro REST dual-registers only while Compatibility Mode is on

## Scenario

Pro registers developer REST on `publishpress-cart/v1` only. Compatibility Mode
dual-registers leftover `sc/v1` onto the same Pro webhook/orders/products/customers/subscriptions
callbacks so Zapier bookmarks keep working while the toggle is on. Gutenberg
block REST stays canonical-only.

## Steps

1. With Compatibility Mode off, assert leftover `/sc/v1/webhook/zap-validate`
   is not registered.
2. Enable Compatibility Mode and call leftover REST registration.
3. Assert leftover Pro webhook is registered with the canonical callback.
4. Dispatch `POST /sc/v1/webhook/zap-validate` and assert the status is not 404.
5. Assert leftover `/sc/v1/checkout-block/products` is still absent.

## Expected result

Leftover Pro REST is absent while Compatibility Mode is off and registered while
on. Gutenberg leftover REST stays unregistered in both modes.

## Edge cases

- No Pro dual-register. Canonical routes exist with Compat off and on.
- Prefix matcher rejects Gutenberg suffixes (UT-309).
