# Leftover $scFiles / $sc_product_fields / $sc_is_studiocart_admin_screen alias only while Compatibility Mode is on

## Scenario

Slice 31 stores files, product metaboxes, and the admin-screen flag on
`$ppcart_files`, `$ppcart_product_fields`, and `$ppcart_is_admin_screen`.
Compatibility Mode off must not create leftover `$scFiles`,
`$sc_product_fields`, or `$sc_is_studiocart_admin_screen`. Compatibility Mode
on aliases those leftover names onto the canonical globals by reference.

## Steps

1. With Compatibility Mode off, assert leftover names are absent. When
   `$ppcart_files` / `$ppcart_product_fields` exist after bootstrap, assert
   they are `PPCart_Files` / `PPCart_Product_Metaboxes`.
2. Enable Compatibility Mode and call `maybe_register_globals()`.
3. Assert leftover `$scFiles` and `$sc_product_fields` are the same values as
   the canonical globals, and writes through either name stay in sync.
4. Assign `$ppcart_is_admin_screen` (not set at bootstrap) and assert leftover
   `$sc_is_studiocart_admin_screen` stays in sync.

## Expected result

- Leftover `$scFiles`, `$sc_product_fields`, and
  `$sc_is_studiocart_admin_screen` exist only while Compatibility Mode is on,
  as references to the canonical `$ppcart_*` globals.

## Edge cases

- IT-263 already asserts mapped leftover names are absent while Compatibility
  Mode is off, including these three after this map row.
- `$ppcart_files` is constructed only when Pro is not loaded.
- `$ppcart_is_admin_screen` is write-only during enqueue and is not set at
  bootstrap.
- Writes through leftover names must not remain after Compatibility Mode is
  turned off in a later request; this process keeps the alias until teardown
  unsets the leftover key.
