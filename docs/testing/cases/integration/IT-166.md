# PPCart_Order registers NCS_Cart_Order and ScrtOrder aliases when Compatibility Mode is on

## Scenario

After the #629 model rename, `PPCart_Order` is the canonical order class. Third-party plugins that still reference `NCS_Cart_Order` or `ScrtOrder` must receive working aliases when Compatibility Mode is enabled.

## Steps

1. Enable `_ppcart_compatibility_mode`.
2. Call `PPCart_Studiocart_Compatibility_Mode::maybe_register_aliases()`.
3. Assert `class_exists( 'PPCart_Order', false )`, `class_exists( 'NCS_Cart_Order', false )`, and `class_exists( 'ScrtOrder', false )`.
4. Construct `new NCS_Cart_Order()` and `new ScrtOrder()` and assert each is an instance of `PPCart_Order`.

## Expected result

All three class names resolve to the same canonical order model when Compatibility Mode is on.

## Edge cases

- With Compatibility Mode off (`test_IT_166_PPCart_Order_legacy_aliases_unregistered_when_mode_is_off`), `NCS_Cart_Order` and `ScrtOrder` must not be registered even though `PPCart_Order` is loaded.
