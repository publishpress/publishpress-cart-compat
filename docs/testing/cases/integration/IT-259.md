# Hook bridges dual-fire legacy listeners and cron drain

## Scenario

First-party code fires canonical `ppcart_*` hooks. Legacy `sc_*` / `studiocart_*` listeners run only when Compatibility Mode is on. Cron drain forwards legacy scheduled hook names to canonical handlers without Compatibility Mode.

## Steps

1. With Compatibility Mode off, fire `ppcart_after_order_paid` and assert a legacy `sc_after_order_paid` listener does not run.
2. Enable Compatibility Mode, fire the canonical hook, and assert legacy and extra `studiocart_checkout_complete` listeners run.
3. With Compatibility Mode on, fire `sc_before_load` and assert a `ppcart_before_load` listener runs.
4. With Compatibility Mode off, fire `nsc_run_price_formatting` and assert the canonical `ppcart_run_price_formatting` listener runs via cron drain.
5. Assert checkout payment template does not contain `studiocart_checkout_complete`.

## Expected result

Canonical hook names work in first-party code while legacy listeners and cron schedules keep working through the Compatibility Mode package only.
