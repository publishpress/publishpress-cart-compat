# CPT slug migration prefixes leftover order post_status

## Scenario

Merchant Data migration step 1 rewrites leftover `sc_order` posts onto
`ppcart_order`. Cart now stores canonical order `post_status` as `ppcart_paid`
while logical `_ppcart_status` stays `paid`. The CPT migrator must prefix
`paid` when it moves an order onto the canonical type, and unprefix on restore.
This is merchant-started, not a silent boot migrate.

## Steps

1. Insert leftover `sc_order` with `post_status` `paid`.
2. Run `PPCartComp_Cpt_Slug_Migrator::run_step1_chunk()` until the post type is canonical.
3. Restore step 1.

## Expected result

- After migrate: `post_type` is `ppcart_order` and `post_status` is `ppcart_paid`.
- After restore: `post_type` is `sc_order` and `post_status` is `paid`.

## Edge cases

- Product leftover rows (`publish`) are unchanged besides post type.
- Mapping is skipped if Cart's `PPCart_Status_Labels::registered_slug()` is absent.
