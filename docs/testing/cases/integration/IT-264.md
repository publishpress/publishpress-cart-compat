# Compatibility Mode aliases legacy runtime globals bidirectionally

## Scenario

When Compatibility Mode is enabled, `$sc_stripe`, `$sc_currency`, `$sc_currency_symbol`, `$sc_debug_logger`, and `$scp` become references to the canonical `$ppcart_*` globals. A leftover legacy value is copied inbound when the canonical name is missing.

## Steps

1. Set `$GLOBALS['scp']` while `$ppcart_product` is unset, enable Compatibility Mode, and call `maybe_register_globals()`.
2. Assert the inbound product object is visible as `$ppcart_product` and writes through `$scp` update it.
3. Write `$ppcart_currency`, `$ppcart_currency_symbol`, `$ppcart_stripe`, and `$ppcart_debug_logger` and assert the matching `$sc_*` names see the same values.
4. Write a legacy name and assert the canonical global updates.

## Expected result

Every renamed runtime global is a bidirectional alias for third-party code, and only while Compatibility Mode is on.
