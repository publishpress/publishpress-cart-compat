# Data migration renames leftover Pro affiliate tables; Compatibility Mode rewrites leftover SQL

## Scenario

Merchant-started `ppcart_migrate_custom_tables()` must `RENAME TABLE` leftover
Pro affiliate tables to canonical `ppcart_*` names and ALTER leftover
`ncs_affiliate_id`. Plugin upgrade does not do this. After migration,
Compatibility Mode rewrites leftover table names in SQL onto the live
canonical names. There is no silent migrate.

## Steps

1. Create leftover Pro affiliate tables with a marker row.
2. Run `ppcart_migrate_custom_tables()`.
3. Confirm leftover tables are gone, canonical tables exist, and the marker row survived.
4. Confirm leftover SQL is unchanged with Compatibility Mode off.
5. Enable Compatibility Mode and rewrite leftover SQL.
6. Repeat migrate with Compatibility Mode already on; leftover object-id
   `SHOW COLUMNS` probes must still find `ncs_affiliate_id` and ALTER it.

## Expected result

Leftover Pro tables are renamed, the affiliatemeta object-id column is
canonical (`bigint unsigned` preserved), rows are preserved, and leftover SQL
rewrites only while Compatibility Mode is on. Migration with the mode already
on still ALTERs the leftover object-id column.

## Edge cases

- Live-table leftover rewrite without Compatibility Mode is UT-313 / UT-220.
- Free tax/order-item rename remains IT-301–305.
