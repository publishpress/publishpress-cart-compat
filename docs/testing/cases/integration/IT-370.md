# Data migration replaces empty canonical order item tables

## Scenario

A store activates Cart before this plugin, so Cart creates empty
`ppcart_order_items` / `ppcart_order_itemmeta` beside leftover tables with
rows. `ppcart_migrate_custom_tables()` must swap the empty canonical tables out
and rename the leftover tables in (publishpress/publishpress-cart#934).

## Steps

1. Create leftover tables with a marker order item.
2. Create empty canonical order item tables.
3. Confirm the leftover table is live and pending.
4. Run `ppcart_migrate_custom_tables()`.
5. Repeat with rows in the canonical table.

## Expected result

Empty canonical: no errors, `replaced_empty` is recorded, leftover tables and
the `*_replaced` tables are gone, and the marker row is in the canonical table.
Canonical with rows: `conflict_both_exist` and both tables stay. Both
tables empty: `leftover_empty`, no error, and both tables stay. Cart schema
setup (activate, upgrade, order items, downloads) while the leftover table is
live does not add canonical columns to it or touch its rows.

## Edge cases

- Plain rename without a canonical table is IT-301.
