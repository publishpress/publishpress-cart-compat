# Step 2 renames leftover roles and can be restored

## Scenario

Role slug migration waits until step 1 is complete. Then leftover
`sc_cart_manager` is renamed to `ppcart_manager` and assigned users
move with it. Restore puts the leftover role and user assignment back and
consumes step 2 backup rows.

## Steps

1. Call `run_step2()` while step 1 is idle.
2. Insert leftover `sc_cart_manager` and a user assigned only to that role.
3. Mark step 1 complete and run step 2.
4. Call `restore_step2()`.

## Expected result

Step 2 is rejected with `step1_incomplete` until step 1 is complete. After
step 2 the leftover role is gone, the user has `ppcart_manager`, and
backup rows exist. Restore recreates `sc_cart_manager`, reassigns the user,
sets `step2` idle, and leaves no backup rows.

## Edge cases

- A fresh WPLoader site already has canonical `ppcart_manager` from
  activate; leftover `sc_cart_manager` is injected by the test.
