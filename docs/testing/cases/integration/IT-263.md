# Legacy runtime globals stay unaliased while Compatibility Mode is off

## Scenario

Canonical checkout globals are `$ppcart_stripe`, `$ppcart_currency`, `$ppcart_currency_symbol`, `$ppcart_debug_logger`, `$ppcart_product`, and `$ppcart_public`. With Compatibility Mode off (the default), the shipped StudioCart names must not exist in `$GLOBALS`.

## Steps

1. Assert Compatibility Mode is off and `legacy_globals_registered()` is false.
2. For every mapped legacy name (`$sc_stripe`, `$sc_currency`, `$sc_currency_symbol`, `$sc_debug_logger`, `$scp`, `$studiocart`), assert the `$GLOBALS` key is absent.
3. Assert bootstrap still populated `$ppcart_debug_logger`, `$ppcart_currency`, `$ppcart_stripe`, and `$ppcart_public`.

## Expected result

First-party runtime globals are `ppcart_*` only. Legacy global names stay Compatibility Mode surface area.
