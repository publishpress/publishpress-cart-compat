# Public query vars and rewrites canonicalize legacy URLs

## Scenario

Core exposes only `ppcart-*` public query vars and download rewrites.
Compatibility Mode conditionally resolves old query strings (`sc-*` plus
leftover checkout `coupon` / `plan`) and builds an equivalent canonical
same-site URL without changing the pretty-download rule.

## Steps

1. Inspect core query-var and download-rewrite registration with the mode off.
2. Enable Compatibility Mode and verify legacy query vars are registered while
   the canonical rewrite remains unchanged.
3. Canonicalize several legacy keys in one URL while preserving another query
   argument and a zero value.
4. Verify an existing canonical value wins when both key forms are present.
5. Exercise array-shaped input and canonical no-loop handling.
6. Verify canonical pretty downloads resolve directly, explicit legacy download
   query strings redirect, and a stale resolved legacy var is canonicalized.
7. Verify the add/update option hooks derived from `ppcart_download_slug`.

## Expected result

Core registers only canonical names. Compatibility Mode adds legacy names and
maps safe requests in one temporary redirect without dropping unrelated query
arguments or replacing canonical values. Canonical pretty downloads remain
direct in both modes, and the live option hooks use
`add_option_ppcart_download_slug` and `update_option_ppcart_download_slug`.

## Edge cases

- Array-shaped legacy values are not copied into canonical arguments.
- Canonical query vars alone never produce another redirect.
- When both forms are present, the legacy key is removed and canonical wins.
- A stale resolved `sc-download` var can redirect without a legacy rewrite.
- Rewrite globals are isolated and restored by the test.
