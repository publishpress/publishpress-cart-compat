# Leftover option-name sensitivity works only when Compatibility Mode is on

## Scenario

Unmigrated leftover `_sc_*` option rows stay in place. Canonical
`get_option('_ppcart_*')` still reads them through the existing storage
bridge. Leftover PHP names are sensitive only while Compatibility Mode is
on. Secrets raw read does not dual-read leftover keys.

## Steps

1. Seed leftover `_sc_mailchimp_api` and leave the canonical row absent.
2. With Compatibility Mode off, assert leftover names are not sensitive and
   `get_raw_option_value('_ppcart_mailchimp_api')` is empty.
3. Confirm `get_option('_ppcart_mailchimp_api')` still returns the leftover
   value and the leftover row is unchanged.
4. Enable Compatibility Mode and assert leftover secret names are sensitive.
5. Confirm the leftover row is still not copied onto the canonical key.

## Expected result

Leftover option-name sensitivity is Compatibility Mode only. Canonical
`get_option` still read-throughs leftover rows. Secrets raw read stays
canonical-only. Stored leftover rows are not rewritten.

## Edge cases

- Leftover `_sc_custom_api_key` matches leftover regex only while Compatibility
  Mode is on.
- Leftover `_sc_currency` stays non-sensitive.
