# Shipped class aliases stay unregistered while Compatibility Mode is off

## Scenario

Migrating the layer into a user-toggleable module means aliases must not register on a default install. After a normal plugin load with `_ppcart_studiocart_compatibility_mode` unset, third-party names such as `ScrtOrder` must not exist even though canonical classes like `PPCart_Order` are loaded.

## Steps

1. Ensure the Compatibility Mode option is not set.
2. Confirm `ppcart_cart_supports( 'studiocart-compatibility-mode' )` is false.
3. For each shipped alias pair whose canonical class is loaded, assert the legacy class name is not registered.

## Expected result

Compatibility Mode is off. Loaded canonical classes do not expose their StudioCart legacy names.

## Edge cases

- Canonical classes that are not loaded (Pro-only or Elementor widgets) are skipped; the old helper also skipped those.
