# Enabling Compatibility Mode registers the shipped StudioCart class aliases

## Scenario

Third-party plugins that still construct `ScrtOrder` (and the other shipped legacy names) must work when a merchant turns Compatibility Mode on. Enabling the option and running the module's alias registrar must create the same map the old `legacy.php` helper registered.

## Steps

1. Run after IT-162 so aliases have not been registered yet.
2. Save `_ppcart_studiocart_compatibility_mode` as `1`.
3. Call `PPCart_Studiocart_Compatibility_Mode::maybe_register_aliases()`.
4. For each shipped pair whose canonical class is loaded, assert the legacy name aliases it.
5. Construct `new ScrtOrder()` and assert it is an `PPCart_Order`.

## Expected result

Every loaded canonical class from the shipped map has a working legacy alias. `new ScrtOrder()` returns an `PPCart_Order` instance.

## Edge cases

- Pairs whose canonical class is not loaded remain unregistered, matching the old helper.
- Depends on IT-162 because `class_alias` cannot be undone in-process.
