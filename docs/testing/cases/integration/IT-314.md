# Checkout runtime globals are canonical and leftover aliases only when Compatibility Mode is on

## Scenario

Slice 22 stores checkout request-render and block-arrangement state on `$GLOBALS['ppcart_*']`. Compatibility Mode off must not create leftover `sc_checkout_*` keys. Compatibility Mode on aliases leftover keys onto the canonical globals.

## Steps

1. With Compatibility Mode off, claim a checkout request render and set block arrangement.
2. Assert canonical keys exist and leftover `sc_checkout_*` keys are absent.
3. Enable Compatibility Mode and call `maybe_register_globals()`.
4. Write canonical checkout globals and assert leftover names see the same values; write leftover names and assert canonical updates.

## Expected result

- `ppcart_checkout_claim_request_render()` and `ppcart_checkout_get_arrangement_context()` use canonical `$GLOBALS` keys.
- Leftover `sc_checkout_request_rendered` and `sc_checkout_block_arrangement` exist only while Compatibility Mode is on, as references to the canonical keys.

## Edge cases

- `ppcart_checkout_reset_request_render_guard()` unsets the canonical key, not a leftover name.
- Admin / REST / AJAX requests skip the duplicate-render guard; this case still locks the `$GLOBALS` key names the storefront writes.
