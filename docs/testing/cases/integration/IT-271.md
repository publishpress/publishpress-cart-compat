# Restore step 1 undoes leftover kinds without acknowledging the notice

## Scenario

After step 1 finishes, restore undoes leftover orders, subscriptions, product
taxonomies, the FSE product template, and capability swaps from the reverse
map. It does not treat the merchant as having dismissed the leftover notice.

## Steps

1. Insert leftover orders, subscriptions, cat/tag terms, the
   `single-sc_product` template, and a throwaway role with a leftover cap.
2. Run step 1 until done and confirm backup rows exist.
3. Call `restore_step1()`.
4. Reload the rows and migration state.

## Expected result

Each leftover kind is back on its StudioCart slug. `ack` is not `later`.
`step1` is idle and `mode` is legacy. Backup rows for step 1 are gone.

## Edge cases

- Restore only undoes rows already in the backup table.
