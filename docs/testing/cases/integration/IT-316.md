# Leftover transient rows read in place; explicit copy; leftover names need Compatibility Mode

## Scenario

Leftover `_transient_sc_*` / `_transient_timeout_sc_*` rows are readable under
canonical names without mutation. Explicit Data migration
(`ppcart_maybe_copy_leftover_option_rows`) may copy them onto canonical keys.
Compatibility Mode maps leftover `get_transient('sc_*')` onto canonical rows.
Mode off does not bridge leftover names.

## Steps

1. Seed leftover `_transient_sc_*` plus timeout. Assert canonical
   `get_transient` returns the value and leftover rows remain. Run the option
   copier explicitly; assert canonical exists and leftover is gone.
2. Enable Compatibility Mode and assert leftover `get_transient('sc_*')`
   returns the canonical value.

## Expected result

Read-through never renames transient option rows. Explicit migration moves
them; canonical wins. Leftover PHP names work only while Compatibility Mode is
on.

## Edge cases

- Object-cache leftover transients are not copied (documented gap).
- First-party Cart writes of `ppcart_*` transients stay in PublishPress Cart
  (same case id, first-party half).
- Boot must not call the option-key copier.
