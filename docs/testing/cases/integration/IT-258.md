# Canonical option writes persist canonical rows

## Scenario

First-party `update_option('ppcart_*')` stores a canonical `wp_options` row. Leftover PHP names work only when Compatibility Mode API bridges are on.

## Steps

1. `update_option('ppcart_admin_email', ...)`.
2. Assert a `ppcart_admin_email` row exists and `sc_admin_email` does not.
3. With Compatibility Mode off, assert `get_option('sc_admin_email')` does not return the stored value.
4. Enable Compatibility Mode and assert `get_option('sc_admin_email')` returns the canonical value.
5. Update via the canonical name and assert the leftover row is still absent.

## Expected result

Canonical PHP option names persist canonical database rows. Compatibility Mode still exposes leftover PHP names after leftover rows are gone.
