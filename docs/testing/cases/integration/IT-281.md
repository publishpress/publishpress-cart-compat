# Leftover post-meta hydrates, writes are canonical, and the migrator copies leftover rows

## Scenario

Stores that still have leftover `_sc_*` post/user-meta must keep hydrating known objects after the write cutover. New writes persist `_ppcart_*` only. Compatibility Mode leftover `get_post_meta()` names hit the canonical row after the leftover row is gone. Query leftover keys stay gated by Compatibility Mode. The merchant-run migrator copies leftover-only rows and deletes leftover when both keys exist.

## Steps

1. Seed leftover-only `_sc_amount` on an order. `ppcart_get_post_meta()` and `ppcart_setup_order()` return it.
2. Call `PPCart_Order::update()`. Assert `_ppcart_*` is written and leftover is not forked.
3. Seed both keys with different values. Get returns canonical.
4. Delete leftover `_sc_amount`, enable Compatibility Mode, and `get_post_meta(…, '_sc_amount')` still returns canonical.
5. Repeat the leftover / canonical / both-keys rules for user-meta `_sc_phone`.
6. Run a migrator chunk: leftover-only `_sc_amount` is renamed; a leftover twin next to canonical is deleted without overwriting canonical.
7. `$studiocart->prefix` is `ppcart_`.
8. Enable Compatibility Mode and call `ppcart_update_post_meta()`. Canonical `_ppcart_*` remains after leftover cleanup.

## Expected result

Leftover rows still hydrate. Writes are canonical. Canonical wins. Compatibility Mode leftover names keep working after copy. The migrator does not overwrite canonical.

## Edge cases

- Query helpers include leftover keys only while Compatibility Mode is on.
- Skip leftover option key `_sc_studiocart_compatibility_mode` (13a / UT-201).
