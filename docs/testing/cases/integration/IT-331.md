# Uninstall cleanup drops reverse-map backups only when opted in

## Scenario

When `ppcartcomp_drop_migration_backups_on_uninstall` is `'1'`, uninstall cleanup drops the three reverse-map backup tables and deletes that flag option. Cart store tables, leftover StudioCart rows, Compatibility Mode, and migration-state options stay. Unset or `'0'` is a no-op.

## Steps

1. Create the CPT, meta, and shortcode reverse-map backup tables.
2. Plant a leftover `_sc_*` option, leftover post meta, Compatibility Mode, and CPT migration-state option.
3. Call `ppcartcomp_maybe_drop_migration_backups_for_blog()` with the flag unset, then `'0'`.
4. Set the flag to `'1'` and call the helper again.
5. Call the helper again with the flag `'1'` after the tables are already gone.

## Expected result

Unset and `'0'` leave the backup tables. `'1'` drops `{prefix}ppcart_cpt_migration_backup`, `{prefix}ppcart_meta_key_migration_backup`, and `{prefix}ppcart_shortcode_tag_migration_backup`, and deletes the flag option. `ppcart_tax_rate`, leftover options/posts, Compatibility Mode, and migration-state options survive. Missing tables are fine (`DROP TABLE IF EXISTS`).

## Edge cases

- Cleanup must not call migrator `delete_backup()` or load plugin bootstrap.
- Compatibility Mode and wizard migration-state options are not deleted.
