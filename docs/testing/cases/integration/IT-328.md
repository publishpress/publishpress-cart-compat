# Leftover CPT names and FSE template work only from maps or Compatibility Mode

## Scenario

Pro-owned collection queries include leftover `sc_collection` from maps so
unmigrated Pro data still matches. Leftover FSE template slug
`single-sc_product` is registered only while Compatibility Mode is on.
Leftover Pro CPT `sc_collection` registers only when Compatibility Mode is on
and the canonical CPT already exists.

## Steps

1. Call `ppcart_query_pro_post_types('collection')` and assert leftover +
   canonical.
2. With Compatibility Mode off, leftover FSE slugs are empty.
3. Enable Compatibility Mode, register CPT/taxonomy bridges, and assert
   leftover `single-sc_product`.
4. Register canonical `ppcart_collection`, call leftover Pro CPT register with
   Compatibility Mode off then on, and assert leftover `sc_collection` exists
   with `show_ui` false.

## Expected result

Pro queries include leftover from maps. Leftover FSE template names and leftover
Pro CPT slugs exist only after Compatibility Mode registers them. Missing
canonical families are skipped.

## Edge cases

- First-party Admin Screens constants stay in PublishPress Cart (same case id,
  first-party half).
