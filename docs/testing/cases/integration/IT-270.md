# Step 1 migrates leftover orders, terms, templates, and caps

## Scenario

A merchant-started step 1 walk migrates leftover orders, subscriptions,
product taxonomies, the FSE `single-sc_product` template, and leftover
capabilities on a throwaway role. Unmapped post types such as Pro
`sc_collection` stay put. Each rename writes a reverse-map backup row.

## Steps

1. Insert leftover `sc_order`, `sc_subscription`, `sc_product_cat`,
   `sc_product_tag`, `wp_template` named `single-sc_product`, and a throwaway
   role with `sc_manager_option`.
2. Insert an unmapped `sc_collection` post.
3. As an administrator, run step 1 chunks until done.
4. Reload the rows.

## Expected result

Orders and subscriptions become `ppcart_*`. Taxonomies become
`ppcart_product_cat` / `ppcart_product_tag`. The template slug becomes
`single-ppcart_product`. The throwaway role has `ppcart_manager_option` and
not `sc_manager_option`. `sc_collection` is unchanged. The backup table has
at least one row.

## Edge cases

- One chunk only migrates the first leftover family; tests loop until done.
- Administrator capabilities are not used as the cap-swap fixture.
