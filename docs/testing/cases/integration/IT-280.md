# Leftover option rows copy onto canonical keys

## Scenario

Stores that still have leftover `_sc_*` / `sc_*` `wp_options` rows must keep working after the storage cutover. The copier copies leftover blobs onto canonical keys (canonical wins when both exist), deletes leftover, and skips the leftover Compatibility Mode toggle. Secret ciphertext is copied as-is.

## Steps

1. Seed leftover-only `sc_admin_email`. `get_option('ppcart_admin_email')` copies it; leftover is deleted.
2. Seed both rows with different values. Copier keeps canonical and deletes leftover.
3. After leftover is gone, enable Compatibility Mode and `get_option('sc_admin_email')` still returns the canonical value.
4. Seed leftover `_sc_studiocart_compatibility_mode`. Copier leaves that row alone.
5. Seed leftover `_sc_stripe_test_sk` ciphertext. `get_raw_option_value('_ppcart_stripe_test_sk')` then the copier leave the same blob on the canonical row.

## Expected result

Leftover mapped options become canonical rows. The leftover Compatibility Mode toggle is not this copier’s job. Secret ciphertext is not re-encrypted during copy.

## Edge cases

- Copy-on-read and the boot copier share `ppcart_copy_leftover_option_row()`.
- Autoload is copied from the leftover row when the canonical row is created.
