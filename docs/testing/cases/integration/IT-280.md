# Leftover option rows read in place until explicit Data migration

## Scenario

Stores that still have leftover `_sc_*` / `sc_*` `wp_options` rows must keep
working without silent renames. Storage bridges read leftover blobs in place.
Boot and Compatibility Mode must not copy or delete option rows. Only an
explicit Data migration call (`ppcart_migrate_option_keys` /
`ppcart_maybe_copy_leftover_option_rows`) may copy leftovers onto canonical keys
(canonical wins when both exist) and delete leftover. The leftover Compatibility
Mode toggle is excluded from that copier. Secret ciphertext is copied as-is when
migration runs. The wizard persists `ppcart_option_key_migration` completion.

## Steps

1. Seed leftover-only `sc_admin_email`. `get_option('ppcart_admin_email')`
   returns the value; leftover row remains; canonical row is not created.
2. Re-register storage bridges (boot path). Leftover row is still present.
3. Seed both rows with different values. Read returns canonical; leftover stays
   until explicit `ppcart_maybe_copy_leftover_option_rows(true)`, which keeps
   canonical and deletes leftover.
4. After explicit migration, enable Compatibility Mode and
   `get_option('sc_admin_email')` still returns the canonical value.
5. Seed leftover `_sc_studiocart_compatibility_mode`. Copier leaves that row alone.
6. Seed leftover `_sc_stripe_test_sk` ciphertext. Raw read works without
   mutating; explicit migration leaves the same blob on the canonical row.

## Expected result

Leftover mapped options stay until Data migration. Read-through never mutates.
The leftover Compatibility Mode toggle is not this copier’s job. Secret
ciphertext is not re-encrypted during copy.

## Edge cases

- Read-through and the migration copier are separate. Boot must not call the
  copier. Copy-on-read is forbidden.
